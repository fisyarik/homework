## проектирование БД
процесс создания схемы базы данных и определния необходимых ограничений целостности

**Основные задачи**
1. хранение в БДвсей необходимой информации
2. Получение данных по всем необходимым запросам
3. Сокращение избыточности и дублирования данных
4. Обеспечение целостности данных (исключение противоречий, предотвращение потерь)

**этапы проектирования**
1. *сбор данных*
2. *концептуальное проектирование* - создание концептуальной модели данных, исходя из представлений пользоательской и предметной области
3. *логическое проектирование* - преобразование концептуальной модели на основе выбранной модели данных в логическую модель, не зависящую от особенностей СУБД
4. *физическое проектирование* - описание конкретной реализации базв данных

Основная цель - отделение пользовательского представления о данных от их физического представления

Внешнее представление - для специалиста предметной области(пользователя), работают только с интерфейсом, с элементами упракления

Внешнее представление и логическая модель - для прикладного программиста

Программисты разрабатывают: 
 - пользовательский интерфейс и функционал приожения(это связано с предметной областью)
 - взаимодействие с логическими структурами данных( абстракция, не связанная с предметной областью)

Логическая модель и внутреннее - для администратора юазы данных

**Терминология**
Сущность - то о чем будут накапливаться данные в БД
Сильная (Правильная) сущность- не зависит от существования других объектов
Слабая сущность - не может существовать при отсутствии некоторой другой сущности
Атрибут - поименованое свойство(характеристика) сущности
Совокупность аторибутов = запись об объекте
Экземпляр сущностей - конкретная сущность. Экземпляры сущностей должны однозначно индефицироваться по одному или нескольким атрибутам
Связь(отношение) - описывает имеющуюся в предметной области логическую связь между сущностями

Нотация Чена - мы можем прописать сущности, их атрибуты в виде диаграммы
Нотация мартина - ее особенность что в ней наглядно видно на разных стрелках какие тип связей между таблицами данных

Этапы построения локальной модели:
1 Этап 
   1. Построение локальных моделей
   2. Объединение локальных моделей
2 этап
   1. Выбор модели данных
   2. Определение наборов структурированных данных. Нормализация твблиц
   3. Проверка модели данных на предмет выполнения всехтранзакций базнес-процессов
   4. Определение требований поддержки целостности данных

Логическое проектирование БД

- Сущности концептуальной м модели описываются как записи, состоящие из полей
- Каждый атрибут описывается как поле с типом и характеристиками, возможными в выбранной модели данных
- связи концептуальной модели описываются в понятиях, соответствующих, выбранной модели данных
- Определяется порядок реализации

## Лабораторная 2

| Команда/Оператор | Описание | Пример использования |
|---------------|----------|--------------------|
| `SELECT *` | Выбор всех столбцов таблицы | `SELECT * FROM Академик` |
| `SELECT <столбцы>` | Выбор конкретных столбцов | `SELECT ФИО, Дата_рождения FROM Академик` |
| `+` | Конкатенация строк или арифметическое сложение | `N'Академик ' + ФИО + N'Специализация: ' + Специализация` |
| `AS` | Задание псевдонима столбцу | `AS Информация` |
| `DISTINCT` | Отбор уникальных значений | `SELECT DISTINCT Специализация FROM Академик` |
| `ORDER BY` | Сортировка результатов | `ORDER BY Год_присвоения_звания` |
| `TOP N` | Ограничение вывода первыми N строками | `SELECT TOP 2 * FROM Академик` |
| `TOP N PERCENT` | Ограничение вывода первыми N % строк | `TOP 30 PERCENT` |
| `WITH TIES` | Включение строк с одинаковым значением сортировки (с `TOP`) | `TOP 4 WITH TIES` |
| `OFFSET N ROWS` | Пропуск первых N строк | `OFFSET 2 ROWS` |
| `FETCH NEXT N ROWS ONLY` | Возврат N строк после пропуска (с `OFFSET`) | `FETCH NEXT 8 ROWS ONLY` |
